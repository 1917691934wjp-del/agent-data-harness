# 简历与面试：Agent Runtime & Evaluation Harness

## 项目名称

面向多数据源 NL2SQL 的 Agent 运行与评测 Harness

## 可使用的项目描述

基于 LangGraph 多智能体数据查询系统构建统一 AgentHarness，将 CLI、Web UI、A2A 和评测入口接入同一运行策略，复用规划、依赖调度、人工审核和检查点恢复能力。

- 设计请求级 Budget 与上下文隔离，约束模型调用、SQL/代码执行、修复重试、任务数量和并发，结合请求/模型/任务超时与取消传播，防止无界执行。
- 实现节点与模型父子 Span、调用和 Token 统计、可选 metadata-only 本地记录，支持异常定位及会话多轮追踪。
- 在 SQL 只读校验上增加数据源允许列表、字段限制、结果脱敏和行数控制，默认阻止模型生成代码在宿主机执行。
- 扩展依赖图和关联键的确定性断言，加入按证据评分的可选 LLM Judge，并将 Judge 用量与被测 Agent 分开记录。
- 建立基线比较、质量/资源阈值门禁、JSON/HTML 报告和离线 CI 配置，检查路由、结果、规划、答案质量和资源使用变化。

## 面试解释

“原系统已有 LangGraph、SQL 校验、人工审批与评测。我把运行策略放到统一入口，在模型和工具边界检查预算。并行 worker 共享请求预算，不同请求的状态与回调隔离。结果优先由确定性断言检查，自然语言回答才采用可选 Judge。报告接入基线比较与门禁，形成运行、观察、评测和回归闭环。”

## 技术取舍

- Token/费用在响应后结算，最后一次或并发调用可能超额；已配置预算且用量缺失时拒绝继续执行。
- 异步取消不等于数据库服务器停止查询，需驱动超时和服务端取消支持。
- SQL/字段策略不等于完整提示词注入防护，数据库权限仍是基础。
- Judge 是辅助评分，不是真值来源；不能代替表格相等或依赖图检查。
- LocalExecutor 不提供沙箱，统一入口默认拒绝其代码执行。

## 实证与措辞

报告离线测试数量、预算阻断、HITL 恢复、合成回放的预期失败和门禁退出码。未有真实数据时，不填写“准确率提升 X%”“成本降低 X%”“生产可用性 99.9%”或“已上线”。后续用固定业务数据集运行基线和候选模型，再填写有报告支持的指标。

多用户改造后已运行 145 项离线回归测试，全部通过。合成回放 25/30 包含故意错误，仅用于验证评分器，不作为模型准确率。

2026 年 10 月 8 日真实调用 DeepSeek deepseek-flash，使用固定本地样例数据与 30 个案例进行 live benchmark：29/30 通过（96.7%），已配置的路由断言正确率为 100%，P95 案例耗时 5.43 秒，模型调用 85 次，累计 200,121 tokens。查询结果类案例 23/24，其余人工确认、多轮和澄清案例 6/6。未启用答案 Judge；这是一轮固定小规模题集的结果，不是生产数据或通用基准成绩。

唯一失败是库存记录数案例触发口径确认而未立即执行。独立补测确认后执行，返回正确结果 125；原基准成绩仍为 29/30。没有可比旧模型基线，不能把合成回放的 25/30 与 live 的 29/30 写成准确率提升。

可用于简历的量化表述：“建立 30 题固定评测集，真实调用 DeepSeek 并执行本地数据查询，本轮案例通过率 96.7%（29/30）、路由断言正确率 100%，P95 案例耗时 5.43 秒；通过 145 项离线回归测试验证编排、HITL、预算与用户隔离。”
